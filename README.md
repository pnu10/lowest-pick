# 최저가픽 — 토스쇼핑 쉐어링크 Open API 연동

토스쇼핑 상품을 큐레이션해 노출하고, 발급받은 **쉐어링크(추적 링크)**를 통한 구매를 제휴 수익으로 정산받는 토스 미니앱.

## 준비 (어드민에서 1회)

쉐어링크 크리에이터 어드민(`sharelink.toss.im`) > API 연동:

1. **Access Key / Secret Key 발급** — Secret Key는 발급 직후 1회만 표시된다. 인증 정보는 사업자 단위로 1개.
2. **출발지 IP 등록** — 내 PC가 아니라 **API를 호출하는 서버의 IP**. 사업자당 최대 10개, 단일 IPv4만(CIDR 미지원). 운영·알파 각각 등록.
3. **퍼블리셔 UUID** — 쉐어링크 발급에 필수. 인증 정보와 함께 안내받는다.

```bash
cp .env.example .env   # TOSS_ACCESS_KEY / TOSS_SECRET_KEY / TOSS_PUBLISHER_ID 채우기
```

알파(테스트) 환경부터 검증하는 것을 권장한다 — 운영과 인증 정보·IP 등록이 분리되어 있다.

## 동기화

```bash
node toss-sync.cjs
```

토큰 발급 → `/health` 연결 확인 → 상품 목록 조회 → 쉐어링크 발급 → `catalog.json` 저장.

| 플래그 | 설명 |
| --- | --- |
| `--today` / `--best` | 하루특가만 / 베스트만 (기본은 둘 다) |
| `--categories` | 1차 카테고리별 베스트까지 추가 (`--per-category N`, 기본 10) |
| `--alpha` | 알파(테스트) 환경 |
| `--min-dc 20` | 할인율 20% 이상만 |
| `--limit 60` | 최대 60건 |
| `--no-link` | 쉐어링크 발급 생략(조회만) |
| `--no-push` | GitHub Pages 배포(커밋·푸시) 생략 |
| `--dry` | 저장하지 않고 결과만 출력 |

### 배포는 동기화에 포함된다

동기화가 끝나면 `catalog.json`·`price-history.json`을 커밋하고 `origin`에 푸시한다.
**이 단계가 없으면 로컬만 최신이고 실제 앱은 옛날 딜을 계속 보여준다** — 앱이 배포 환경에서
`https://pnu10.github.io/lowest-pick/catalog.json`을 읽기 때문이다.

푸시에 실패해도 동기화 자체는 성공으로 처리한다(로컬 파일은 이미 정상이므로). 로그에 경고가 남으니
`sync.log`를 보고 직접 푸시하면 된다.

## ⚠️ 링크는 반드시 발급받은 것만

조회 API가 주는 `productUrl`은 **추적이 되지 않는 일반 링크**라 이 링크로 발생한 구매는 수익으로 집계되지 않는다.
`toss-sync.cjs`는 `productUrl`을 아예 저장하지 않고, `POST /openapi/links`로 발급받은 `shortUrl`만 `url`에 담는다.
발급이 거절된 상품(셀러 정책 등)은 카탈로그에서 제외된다.

발급받은 링크는 `links.json`에 캐시되어 재사용된다. 같은 `tacaItemId` + 같은 `publisherId`면 같은 링크가 나오지만,
매번 호출하면 호출 한도(파트너 단위 10rps)를 낭비하게 된다.

## 하루특가는 `endAt` 전에 다시 돌리기

하루특가는 그날 하루만 판매하고 종료되면 목록에서 자동으로 빠진다. 편성이 없는 날은 **0건**일 수 있다(정상).
저장한 응답을 `endAt` 이후까지 쓰면 이미 끝난 특가가 계속 노출되므로, 동기화 후 로그에 찍히는
"가장 빨리 끝나는 특가" 시각 전에 다시 실행해야 한다. 앱은 `endAt` 기준 카운트다운을 표시한다.

## 카테고리 분류 — 휴리스틱이다

하루특가·베스트 API는 **카테고리를 내려주지 않는다.** 그래서 상품명 키워드로 추정한다(`toss-sync.cjs`의 `CAT_RULES`).
게시판 8종: 생활리빙 · 식품 · 화장미용 · 디지털가전 · 출산육아 · 스포츠레저 · 패션 · 가구인테리어

`CAT_RULES`는 **배열 순서가 곧 우선순위**다. 실데이터로 확인한 함정들:

- `크림치즈`·`복숭아크림찰떡` → '크림'(화장미용)보다 **식품 규칙이 먼저** 와야 한다
- `무선청소기` → '청소'(생활리빙)보다 디지털가전이 먼저
- `수납형 선풍기` → '수납'(가구인테리어)보다 디지털가전이 먼저
- **한글에는 `\b`를 쓰지 말 것** — JS의 `\w`는 ASCII라 `브라\b`는 절대 매치되지 않는다. `브라(?![가-힣])`를 쓴다
- 브랜드는 분류에서 제외한다. 안 그러면 브랜드 "올**리빙**"의 아이스박스가 가구인테리어로 간다
- 단, 브랜드에만 신호가 있는 경우("해태**아이스크림** 부라보콘")를 위해 전체 이름을 마지막에 한 번 더 본다

규칙을 고쳤으면 반드시 회귀 테스트를 돌린다:

```bash
node test-category.cjs
```

키워드 방식이라 장꼬리는 계속 남는다(현재 미분류는 생활리빙으로 떨어진다). 개별 상품을 바로잡으려면
`category-map.json`에 `{"매칭할 문자열": "게시판명"}`을 넣으면 규칙보다 우선한다.

## 브랜드 분리

상품명이 `브랜드 제품명, 옵션, 수량` 형식이라 앞 토큰을 브랜드로 뗀다(`splitBrand`).
완벽하진 않다 — "대만 토종 파인애플 펑리수"의 "대만"처럼 수식어가 브랜드로 잡히기도 한다.
원본은 `fullName`에 남겨둔다.

## 앱 실행

```bash
python3 -m http.server 4334 --directory .
```

로컬에서는 같은 폴더 `catalog.json`을, 배포 환경에서는 `https://pnu10.github.io/lowest-pick/catalog.json`을 먼저 읽는다
(재배포 없이 카탈로그만 갱신하기 위한 구조).

## 알아둘 것

- **성패는 `resultType`으로 판별한다.** 요청 오류도 HTTP 200으로 내려온다.
- 재시도: 429·500만 백오프 재시도(429는 `Retry-After` 우선). 400·401·403·404는 재시도해도 같다.
- `403 IP_NOT_ALLOWED`가 뜨면 출발지 IP 미등록이다.
- 개인화 정보(쿠폰·배송지·적립)는 제공되지 않고, 성인 상품도 조회되지 않는다.
- 제공 데이터는 제휴 목적 범위 내에서만 사용해야 한다. 가격 크롤링·무단 재판매·대량 수집은 차단 사유.
- 정산 조건은 담당자 문의 사항이다.

## 자동 동기화 (launchd)

`com.lowestpick.tosssync` — **매일 07:00, 18:00**에 `toss-sync.cjs`를 돌린다.
18시를 넣은 이유는 하루특가가 오후 5시에 끝나서, 그 직후 새 편성을 받기 위해서다.

```bash
launchctl list | grep tosssync          # 등록·마지막 종료 상태(0이면 성공)
launchctl kickstart -p gui/$UID/com.lowestpick.tosssync   # 즉시 실행
tail -20 sync.log                        # 실행 로그
```

plist: `~/Library/LaunchAgents/com.lowestpick.tosssync.plist`

끄려면:

```bash
launchctl bootout gui/$UID/com.lowestpick.tosssync
```

**주의**
- 맥이 꺼져 있거나 잠들어 있으면 그 시각을 건너뛴다(깨어난 뒤 한 번 몰아서 실행된다). 실행 중 잠들지 않도록 `caffeinate -i`로 감쌌다.
- **공인 IP가 바뀌면 `403`으로 실패한다.** 어드민에 등록한 IP가 유효한지 가끔 확인할 것 (`curl https://api.ipify.org`).
- 실패해도 기존 `catalog.json`은 보존된다(발급 0건이면 덮어쓰지 않음).

앞선 네이버 크롤러 작업(`com.lowestpick.recrawl`)은 2026-08-06에 중지·제거했다.
